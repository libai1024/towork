# ToWork 免费版：技术方案总览

> 更新：2026-09-24。状态：F0/F1 实施中；待办、分类、资料和设置已接本地存储，生产文字聊天已接 Agent 和本地历史，语音已接双端原生适配及可取消自动发送，Agent 支持部分审批、差异刷新和多批撤销。重复系列已接手动范围操作、分类模板联动及前台自动窗口补齐；Agent 系列工具、整体审批、范围差异刷新与撤销已接入；第 018 轮接入 Android 后台维护和每日数据摘要，macOS 继续前台维护；第 019 轮接入长会话上下文裁剪、预算与保留历史提示。第 020 轮补齐 Agent 组合查询、分类发现和完整备注分段读取。第 021–022 轮新增业务表核心持久化、类型校验与统一事务/撤销，主要人工页面及真实历史已接入，第 023 轮接入业务表 Agent 行查询/写入、统一审批和有界读取；截图与完整 schema 管理仍待完成。实际递送矩阵和其他功能仍待完成。见开发进度与[契约草案](contracts/README.md)。
> 用户已确认：此前讨论的云端方案归商业版；免费版采用 **App 本地运行 + 用户 Kimi API Key**，无自建后端，自动云同步不属于默认能力。

## 1. 推荐结论

继续使用现有 **Flutter + Riverpod + go_router**，新增 **Drift / SQLite 本地数据库、纯 Dart Agent 执行循环、Kimi HTTP 流式适配和平台能力适配层**。手动操作与 Agent 工具调用同一组业务命令，所有业务提交、权限判断、撤销和任务恢复都在 App 内完成。

Android 和 macOS 共用应用代码及业务规则，分别接系统语音、通知、后台调度与桌面快捷入口。无需部署 FastAPI、PostgreSQL、Redis、对象存储，也无需把 Pi / oh-my-pi、Node 或 Python 服务塞进 App。已有内置 Agent 产品的可借鉴设计见 案例调研。

“免费”指 App 的产品版本，不代表模型请求免费：Kimi 按用户自己的账户与 Key 使用，相关输入仍会发送到模型服务商。离线时可以查看和手动编辑本地数据；AI 对话、图片理解、AI 总结需要可用网络及模型额度。设备本地模型不是本次默认方案。

## 3. 免费版与商业版的边界

下表没有新增付费定价或订阅规则；商业版描述沿用已有需求，免费版为本次确认边界下的实现建议。

| 能力 | 免费版 | 商业版（此前方案） |
|---|---|---|
| 首版平台 | Android + macOS；iOS 后续 | 相同 |
| 语音/文字、多轮对话 | 本机采集、转写后自动发送，可取消；历史本地保存 | 客户端采集，对话及 Agent 接云端 |
| 待办与重复待办 | 本地完整增删改查、完成、两级分类、标签、优先级、批量、撤销；日/周/月重复 | 云端持久化，客户端离线与同步 |
| 三档操作权限 | App 在每次业务提交前执行统一规则 | 云端执行相同业务规则，客户端展示确认 |
| 任务多视图 | 本地列表、看板、日历、热力图、时间轴、分类分布、趋势 | 客户端展示云端/同步数据 |
| 业务表与截图入表 | 本地表结构、记录、修改历史、原图；选中图片发 Kimi 理解 | 云端表、附件和 Agent |
| 长期记忆 | 本地保存、检索、手动管理、自动提取与暂停；仅相关内容进入模型上下文 | 云端存储和索引 |
| 周/月/自定义报告 | 本地统计，Kimi 写总结；模板海报、PDF/Markdown、本地保存分享及重新生成均保留 | 服务端任务生成产物 |
| 定时报告 | 开放平台配置在系统允许时执行并补跑；Code 配置自动整理本地统计，AI 总结等待用户主动触发及用途核验，详见下文 | 服务端存活时可在客户端离线期间生成 |
| 截止提醒/每日摘要 | 系统本地通知 + 本地任务；设备状态影响送达/计算 | 沿用原通知设计；服务端生成并不自动等于实时推送 |
| Kimi Key 与通断测试 | Key 在系统安全存储；App 直连官方 API；可手动真实测试 | 用户提供 Key，服务器调用与测试 |
| 用户名 | 本地展示名可修改并重启保留；不代表云端身份 | 可修改并云端同步，稳定 user_id 不变 |
| 多设备/账户 | 各设备独立资料库；默认无登录、无自动云同步 | 云端账户、认证与多设备同步 |
| 备份和导出 | 本地备份恢复、全量业务 JSON/CSV；不含模型 Key；可借系统分享转移 | 用户数据导出 + 服务端备份恢复 |
| macOS 入口 | 全局快捷键、菜单栏记录、可选开机自启 | 相同客户端入口 |
| 运维 | 安装 App、配置 Key 即可；用户维护本地备份 | 既有单用户服务部署与云端运维 |

保留功能不等于承诺相同的持续在线能力。本地版无法保证在设备关机、App 被强制停止或 macOS 完全退出后准时调用模型。通知登记与后台计算也属于不同能力，完整状态表见 平台边界。

### 三档权限沿用已确认规则

| 操作 | 自动执行 | 智能确认 | 总是询问 |
|---|---|---|---|
| 查询 | 直接返回 | 直接返回 | 直接返回 |
| 新增 | 执行 | 执行 | 确认后执行 |
| 编辑 | 执行 | 执行 | 确认后执行 |
| 完成待办 | 执行 | 执行 | 确认后执行 |
| 删除 | 执行 | 确认后执行 | 确认后执行 |

权限统一用于待办和业务表。选择“本次全部接受”只批准该批已展示的动作，不切换长期档位。记忆暂停属于独立写入约束，任何档位都不能绕过。名称、默认档位以及切换确认的最终文案仍按产品细化决定。

## 4. Kimi 接入有一项重要选型区别

用户进一步明确当前持有 **Kimi Code 199 元编程订阅**，按独立 Code profile 核验接入，不与开放平台 Key 混用。面向自有产品的默认接入仍推荐 Kimi 开放平台；Code 的个人交互式使用范围还影响无人值守 AI 周报。具体事实、设计限制与任务映射见 Code 订阅接入补充。

这是一项基于调研的新建议，不把此前某次 Code Key 调用成功当作所有用户都能使用的产品承诺。若仍要提供 Code 选项，应单独核验用途、接入要求及真实兼容性，再发布对应 profile；不伪装官方客户端，不自动把用户 Key 发往另一服务。具体接入和测试方案见 技术栈。

## 5. 实施组织建议

沿用一个代码仓库，使用依赖注入区分免费本地版和商业远程版；复用页面、领域数据契约、权限规范、海报模板和测试场景。免费版数据库是权威数据源，商业版客户端数据库是离线副本，这两个事实不能被一个含糊的 `Repository` 实现掩盖。

免费版开发分为 **界面与平台角色、端侧核心角色、测试角色**。端侧核心承担原“后端”中的 Agent、业务校验、事务、索引和任务工作，但不建设服务端。先完成“本地持久化 → Key 测试 → 语音增改待办 → 重启不重复写入”的完整闭环，再扩展数据表、记忆、统计和报告。完整任务卡见 免费版路线图，交付概览见 开发与验证顺序。

调研与任务卡不代表功能已实现。真实验证的范围逐轮记录在开发进度，未测平台与能力继续保持待验证；不能以隔离原型替代双端发布包验收。
