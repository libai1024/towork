# 待办步骤

已通过原型评审。覆盖新建、详情、待办列表、会话和快问。已确定的规则是勾完最后一个未完成步骤时，自动完成所属待办。

## 从一条待办开始

「提交物业经费报销」截止今天 18:00。第 1 步「核对发票抬头和金额」已完成，当前进度为 1/3。第 2 步「整理电子发票和付款凭证」标为「下一步」。勾选后，标记移到第 3 步「提交报销单」。最后一项完成时进度达到 3/3，待办同步完成，今日未完成数减一，本次后续提醒取消。详情留在原处，提供「撤销」。

步骤是所属待办内的一层有序清单。日期、提醒、优先级、分类和重复规则由待办持有。每一步只需名称和完成状态。操作对象通过待办 ID 与步骤 ID 共同确定，允许同名步骤。

## 编辑和执行

| 场景 | 交互 |
| --- | --- |
| 新建 | 标题和备注下方提供「添加步骤」。输入后回车继续添加。点右上角「创建」同时提交标题、已添加步骤和当前尚未按回车的非空草稿。取消新建时舍弃整份草稿。 |
| 详情 | 截止时间与返回入口共用顶部一行。步骤紧接备注，进度、添加和整理共用一个标题行。空清单只显示「＋ 添加步骤」。 |
| 顺序 | 步骤从 1 开始编号。细线连接相邻序号，第一个未完成步骤用实心序号和「下一步」标记，已完成行保留序号并在文字旁显示勾。允许按实际工作进度先勾后面的步骤，下一步始终指向排序最靠前的未完成项。 |
| 勾选 | 点击步骤整行即可勾选或取消勾选，位置保持不动。最后一个未完成项可以位于任意位置，勾选它时同步完成父待办。标题前的圆框操作整条待办。 |
| 撤销与重开 | 「撤销」恢复刚才那个步骤和父待办原状态。也可以直接取消任意已勾选步骤，系统随即重开父待办并保留其他勾选。单独点标题旁圆框重开只改变父状态，即使进度仍是 3/3 也可继续添加步骤。 |
| 草稿与清单调整 | 新建草稿在点「创建」时计算初始状态，有步骤且全部勾选则直接存为已完成。已有待办仅在实际勾选最后一项时自动完成。删除最后一个未完成项、移位、打开旧记录或保存空清单均保留父状态。 |
| 改名与整理 | 点「整理」后可在原行改名、上移、下移或删除。调整顺序后立即重排序号并重新定位「下一步」，勾选状态跟随步骤 ID。删除后的「撤销」恢复步骤、位置和勾选状态。 |
| 提前完成 | 剩余步骤大于零时，手动完成父待办先显示「还有 2 个未完成步骤」。确认后结束父待办并保留每一步的真实状态。重新打开后可以接着处理。各入口复用相同的判断。 |
| 关闭与失败 | 已存在待办的步骤编辑逐次保存。退出时等待当前写入，失败保留文字并可重试。新建表单中的步骤作为草稿，随「创建」一次保存。 |

步骤正文使用 14 字号，序号直径 20，序号边缘与文字相距 6 逻辑像素。触屏默认执行行高 38，整行接收点击；整理时的独立图标提供至少 44 × 44 的触控区。长名称与放大字号撑开行高，换行对齐名称。读屏可获取序号、名称、勾选状态和当前步骤。

## 列表、快问和 AI

- 待办列表、看板、今日总览和会话结果共用进度摘要。只有包含步骤的待办显示计数。AI 分页清单维持每页五条，点待办打开详情。步骤数量不计入今日事项总数。
- 用户说「帮我把报销拆成几步」时，AI 在会话中展示建议清单，一次「添加到待办」提交所选步骤。已有步骤在其原位保留。用户点开快问看到与主界面相同的进度。
- 用户明确指定「把核对发票标记完成」时，AI 先读目标清单，用稳定 ID、版本及明确的目标状态提交。两步同名且上下文不能区分时，用快捷选择澄清。操作完成依据已提交回执，工具建议与文字回复本身都不算执行。
- 重复待办勾完最后一步只完成当前日期的实例。当前实例的步骤内容默认只改本次。编辑系列模板时复用「本次及以后」范围，未来实例继承名称和顺序，初始勾选为零。撤销或重新打开后按本次实例现有规则重新计算尚可触发的提醒。

## 数据与实现顺序

1. **共享模型与兼容。** 在不可变 `Todo` 上新增有序 `steps`，单项含 `id`、`title`、`done`。先复用 SQLite 的 `work_todos.payload`，沿用 schema 13。读取旧待办、旧回执及系列模板时将缺失字段视为空清单，导出保留步骤及顺序。外部输入应拒绝重复 ID、空白名称和非法类型。AI 工具查询按既有响应字节预算分页。
2. **持久命令。** 新建扩展现有 `AppendTodo`。已有待办按步骤 ID 增加、改名、设定勾选状态、移位和删除。在同一 SQLite 事务内复核目标版本，基于最新步骤判断是否刚刚全部完成，一次写入步骤、父状态和完成时间，生成一份撤销回执。提交后由现有状态投影更新总览、统计与提醒。相同操作 ID 重试只生效一次。冲突后刷新并保留用户草稿，仅在操作前提仍一致时重放。
3. **共用界面。** 新建与详情复用步骤编辑器，列表复用进度摘要，接入现有 Todo 命令、Toast 和无障碍语义。父待办从详情、列表或会话完成时使用同一套状态规则。
4. **Agent 与系列。** 列表查询提供计数，详情查询才返回步骤。AI 增删改和批量建议复用工具审批与事务。系列模板与实例区分完成状态。工作区统计和自动提醒继续按父待办计算。
5. **发布。** 先用独立数据库和 Android、iOS 模拟器验证迁移兼容、快问交接及冷启动。以当前签名宿主试编译差量，再依据编译结果选择免安装补丁或新基础包。正式发布前验证旧版更新、步骤持久化和备份导出。

## 验收场景

| 操作 | 预期 |
| --- | --- |
| 旧数据、空清单、已完成或已取消的待办 | 正常读取，列表只为有步骤的记录显示进度。已完成项可直接取消一个已勾选步骤以重新打开。已取消项保持只读。 |
| 新建时连输三步，第三步输入后直接点创建，再重试相同操作 | 生成一条待办、三个有序步骤，关闭新建草稿则没有工作区写入。 |
| 两个同名步骤，重排后勾选第二个 | 序号按新位置显示，勾选随步骤 ID 保留。非末个未完成步骤的变化只更新进度。 |
| 先做第 3 步，再把第 2 步移到第 1 位 | 越序勾选后原先的第一项仍是「下一步」。整理后，标记指向新顺序里最靠前的未完成项；全部完成时收起标记。 |
| 从 2/3 勾到 3/3，再点撤销 | 父待办立即完成，撤销回到 2/3 和原先的待处理或进行中状态。整次操作只计一次。 |
| 在 3/3 的已完成待办取消其中一步 | 父待办重新打开，进度回到 2/3。重复提交同一取消操作保持该结果。 |
| 提前结束部分完成的待办、取消确认或重新打开 | 确认才结束待办并保留勾选；取消时提醒继续生效。 |
| 主界面改名，同时快问勾选另一步 | 不丢任一已提交修改。同一步发生冲突时显示当前状态，草稿可恢复。 |
| 删除步骤再撤销，导出备份，关闭进程后重新进入 | 步骤 ID、名称、顺序和状态一致，备份包含可读的步骤内容。 |
| AI 拆解后取消或确认，重复提交确认 | 取消时零写入；确认后一次写入所选步骤；重复提交可读回同一回执。 |
| 勾完本周重复待办，打开下周实例 | 本周显示已完成，下周仍待处理、步骤全未选。撤销本周完成也只影响本周。 |
| 窄屏、大字号、长名称和长清单 | 标题可换行、输入框避开键盘、每个操作可用读屏与触控完成。 |
